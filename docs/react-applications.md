# React applications on the canvas

Application UI uses actual React source files shared across screens. A frame's `react` field selects an entry module, export name and optional JSON props. Shared components are ordinary imports, so editing one Button implementation updates every importing screen. Shadcn, other component systems, charts and motion libraries are supported when their dependencies can run in a browser.

Use `canvas_write_react` to save files and bind a screen together, or `update_react_files` in a normal transaction to merge file/dependency changes. Null deletes a file or dependency; set a node binding to `react: null` to detach it without deleting its geometry or comments. Use exact npm versions; `@/` resolves to `src/`. Imports of browser-compatible packages are bundled locally. Install scripts, server code and Tailwind JavaScript plugins/configs are not executed. Compilation failures preserve the prior saved revision. Syntax/module compilation is not full TypeScript type analysis.

The compiler includes Tailwind 4 theme, preflight and utilities. Import app CSS from an entry or shared module; `@import "tailwindcss"` is handled by the compiler. CSS `@theme` and `@utility` work. Use complete utility names in source strings. Other libraries can bring bundled CSS or CSS-in-JS. Media imports in packages can be embedded as data URLs; external network, storage and backend access are unavailable inside previews. Adapt server frameworks and private data with explicit local preview providers.

React runs inside an opaque-origin iframe. Click a registered inner component to open its own preview and source editor. Double-click a screen background to interact, then press Escape to return to canvas manipulation. Source editing is available in the Code tab with a file selector; errors keep the previous preview saved. Register reusable inner components during screen authoring using the components array on canvas_write_react or upsert_component. The compiler adds selection attributes to JSX elements inside bound exports without adding DOM wrappers or changing the saved source. Use the defining module rather than a barrel re-export, and supply realistic specimen props and provider adapters. The Components library opens the same focused editing page. DOM interiors remain source-editable. Existing saved bundles need one source save/recompile after installing this update; missing component definitions must be registered. Component specimen bindings/props/geometry can use existing releases; the imported module source is shared project-wide and is not pinned by those releases.

HTML exports preserve isolated interactive previews. React exports use real imports and components, never an HTML iframe substitute for React screens. The application/ directory preserves authored files and exact dependency versions, with a Vite entry to run the screens. Use `?screen=src/screens/Home.tsx&export=default` to select an entry. The compiled preview stylesheet is included; configure Tailwind in the destination app or regenerate the stylesheet when adding utility classes. SVG/PNG exports of React screens are unavailable; use HTML, React or Source ZIP.

Existing native/HTML designs are retained. Importing a screen as React is an intentional conversion, not a destructive automatic rewrite. Native editing remains appropriate for wireframes, diagrams and explicitly requested editable layer trees. Fidelity still requires the actual application's fonts, assets, density, component variants and rendered inspection.

The runtime needs npm on PATH for the first installation of each dependency set. Installations are cached under the project store and use no lifecycle scripts. The packaged compiler includes a native build plus a portable fallback.
