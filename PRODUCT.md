# Codex Design

Codex Design is a local design workspace and ChatGPT/Codex plugin for iterating on interfaces and slide decks before implementing them. It supports desktop, laptop, tablet, and mobile layouts, presentation slides, and custom frame sizes. A person and their agent share application projects, feature boards, pages, frames, editable elements, source code, and persistent conversations anchored to components.

A separate standard MCP/browser entrypoint supports other coding harnesses and their own models. It starts a private loopback editor, returns explicit project/board/page URLs and supplies JSON text fallbacks for ordinary MCP clients. Its agent connection omits app-only restore tools; the browser retains History Apply. Browser comments and design-system requests remain queued until the active harness handles them. The Codex plugin keeps its existing stdio entrypoint, embedded pane, host messaging, image integration and storage.

Image/video nodes use reusable persisted assets outside revision JSON. Shader layers provide controlled WebGL presets and custom GLSL, static by default. The compact Export panel supports component/page/board/project scope, React/CSS, HTML, supported SVG source, portable source archives, editable backups and a Codex implementation handoff. Focused component reads preserve ancestors, source, tokens and conversations without sending unrelated screens. Generated code preserves visual structure; the agent connects real app behavior during implementation.

Shift-click adds or removes objects on the canvas and in Layers. Selected objects have individual outlines and shared bounds, with selection-wide move, nudge, duplicate, delete, fit and export actions. Nested selections affect each subtree once and each action saves as one undoable change. Group movement respects locks, hidden ancestry and stack positions. Untransformed, free-positioned selections can resize together; their selected bounds and spacing change while descendant content retains its size. Select one object for individual properties or source. Escape or an ordinary empty-canvas click clears the selection. Codex receives the selected object IDs in the active pane's model context.

Drag from blank canvas space with Select to draw a selection box. Visible object bounds fully enclosed by the box are selected in any drag direction; fully enclosed containers carry their descendants once. Shift-drag adds to the existing selection. The live preview skips locked/hidden ancestry and respects rectangular overflow clipping, including bordered and transformed parents. Releasing accepts the selection; Escape, lost capture, blur or a context/revision change discards the preview and retains the prior selection. Box selection does not edit designs or history. Object dragging and Space/middle-button/Hand panning retain their existing behavior.

Canvas shortcuts accept Command on Mac and Ctrl on Windows/Linux; tooltips and Help show the platform's labels. Undo uses Z, redo uses Shift+Z or Y, duplicate uses D, select/deselect all uses A/Shift+A, and copy/cut/paste uses C/X/V with the primary modifier. Select All selects visible unlocked page roots. Zoom uses +/−, 0 resets to 100%, 1 fits the page and 2 fits the selection. Ordinary text fields, content editing, source selection and open dialogs retain native keyboard/clipboard behavior. Captured primary shortcuts remain usable from toolbar buttons and closed property menus; IME composition and Alt/system-modified shortcuts do not activate canvas tools.

Object clipboard data includes only selected subtrees and their anchored conversations, with source, JSX, media references and effective token fallbacks. Paste assigns fresh IDs, remaps internal native links, suppresses cloned queued requests and saves as one undoable change. Repeated pastes offset the copies. Same-page paste retains an unchanged unlocked free-positioned parent; other supported roots detach at their canvas positions. A transformed ancestor that cannot be preserved requires copying the parent frame or using the unchanged original page. Cross-project native token bindings detach; authored source references remain verbatim and may depend on the destination design system. Clipboard payloads and transactions respect existing size/count validation; unavailable media is rejected by the store. Cut requires a writable clipboard event before removing objects and remains undoable. Native image/video file paste remains supported. The host must deliver keyboard and clipboard events to the active editor pane.

The caret beside Comments opens the current project's complete conversation list across its boards and pages. Open threads appear first and resolved threads below, each newest activity first, with saved requests, reply counts, location and honest queued/Codex-reply indicators. Resolved entries include the latest saved Codex response. Opening an entry navigates to its component or canvas anchor and exposes the full preserved conversation for replying or reopening; it does not send a request. The list also retains the local comment-pin visibility control. Other projects and chats remain separate.

Component comments can request generated imagery through an Image option beside @Codex, or ordinary natural-language instructions. The active agent uses the host's native image tool, reads the selected layout and suitable image regions, and places the generated asset through the normal versioned editor. Image intent and the original prompt remain in the component conversation. Generated assets are copied into durable media storage; source, editable text, controls and surrounding layout are preserved. This requires an active host with image-generation capability; the editor does not run a model itself.

Stakeholder canvas maps export PNG at 1×–4× or a self-contained browser SVG, preserving frame positions within each page and grouping independent pages. Background choices are transparent, white, dark or custom hex, with optional labels and margin. Exact raster pixel dimensions and explicit 16,384-pixel side / 64-megapixel limits are shown; scale is not a claim of print DPI. HTML source, video and shaders are captured as passive stills in browser exports; external resources and unsupported sources report errors. Browser SVG maps use foreignObject/CSS and may not import faithfully into non-browser vector tools.

Closing Export, including Escape or clicking outside, cancels pending export preparation and prevents delayed downloads, clipboard fallbacks and stale notifications. A changed design revision or export scope cancels the previous request and asks the user to export the current revision. Cancellation stops browser media reads; an already dispatched host request or clipboard/download action cannot be recalled. Synchronous archive construction finishes before the browser can handle a close event.

Media imports and file/poster replacements can be cancelled. Navigation and History mode stop active uploads; the agent can discard a pending upload through MCP. Temporary upload bytes are separate from completed assets and design revisions. Cancellation preserves already-added media and cannot undo a save in progress. Disconnected cleanup uses the existing expiry fallback.

Vertical and horizontal stacks support cross-axis alignment and main-axis distribution, including equal spare space between children. Child sizes and minimum gaps remain fixed; hidden children are excluded. Canvas placement, component context, history previews and exports share the same calculation. Free positioning remains the default for existing designs.

Detaching a stack through a parent layout edit preserves its visible direct children's positions in the same atomic save. Nested stacks, source, media and conversations remain intact. Browser and agent edits share this behavior; history snapshots retain exact stored geometry.

Each application project contains independent boards for features or design efforts. Each board has its own pages, screens, source and conversations; design tokens are shared across the project. The project menu opens on recent boards, sorted by last edit, with six shown initially and Load more to reveal the next six. Existing designs become a Main board. Codex handoff targets the active board and can read other boards for context.

Each project owns exactly one editable design system, shared by all boards. Its spatial canvas groups named tokens for color, typography, spacing, corners, borders, shadows, motion, breakpoints and layering. Documentation adds product principles, component anatomy/variants/states, responsive and accessibility rules, implementation mappings, evidence, exceptions and open conflicts. The person can edit tokens and Markdown directly, then copy/download a current DESIGN.md and copy CSS variables. Source and editable exports retain that knowledge.

Font menus render each choice in its font family or weight, with searchable family choices and editable CSS stacks. Properties, Tweaks, the compact toolbar and design-system tokens share the picker. DESIGN.md includes project font controls with live specimens; these choices save directly to the shared tokens. Available local fonts and CSS fallbacks determine previews; choosing a font does not install it.

The DESIGN.md tab edits the complete generated project document. Saving its name, description, guidance and token table applies one validated project revision, updating explicit native bindings and current source CSS variables across boards, components and exports. Stable token variable IDs and section comments preserve identity; component/source catalogs are generated and protected. A changed saved document blocks a stale Markdown draft until the person reviews and uses the latest version. Intentional custom values stay independent. Native token deletion freezes bound values; source declarations and fallbacks remain authored. Repository files are not watched automatically.

Properties can explicitly reference compatible named tokens or use Custom values. Linked changes propagate across boards; custom values remain independent even when their literals match a token. Detaching or deleting a token freezes its current visible value. Literal fallbacks and stable token IDs remain in the document. Spacing resolves before stack positioning; export coordinates represent the approved layout at export time.

Generate and Find existing save an agent request with the app brief and optional repository scope. A connected active agent generates a coherent system or inventories applicable DESIGN.md files first, then production components, screens, styles and configuration across the authorized application. It preserves curated knowledge, records observed/inferred evidence, coverage and conflicts, and saves real results into the same project system. The browser offers a saved prompt when host delivery is unavailable. Queued means pending work; repository discovery and model execution belong to the active agent.

The single Design system title-bar button opens Design system, Components and Inspiration tabs; there is no separate Inspiration title-bar action. Tokens and component definitions span the project; inspiration keeps its board scope.

Native reusable component definitions live in the project design system. Explicit capture turns one selected subtree into a linked instance; placement reuses its definition. Native property changes record local overrides. Releasing an edited instance publishes a new definition version; other instances remain on their saved release until explicitly updated. Updates preserve overrides and conversation IDs and reject removed layers that would discard local work. Detach retains native objects and comments for structural edits. Nested linked components and variants/slots are not yet supported. Visual React/HTML exports expand native instances; editable JSON retains the component relationship.

Design-system and component versions use immutable project history with scoped lists, named releases, read-only previews/comparisons and an explicit Apply. System Apply leaves unrelated canvas work intact; component Apply replaces only its definition. Current instances remain pinned. Recovery history is retained and revision conflicts reject stale writes. Portable backups include current definitions and appearances, not the original project journal; outdated imported instances detach when their release history is unavailable.

Each board has its own Inspiration canvas. The person can paste, drop or import reference images, then edit what they like, intended use and a source link. Durable original assets and annotations persist in history and portable backups. The agent reads this board-specific guidance before designing; references do not implicitly restyle other boards.

The Inspiration editor includes a compact, clickable image drop zone with a file-drag highlight and concise Browse/paste hint. The zone and canvas share the same import validation, board limits and upload cancellation. Empty boards avoid redundant instructions.

Each chat keeps its own project, board and page selection, restored through its canvas context and optional host conversation identity. The global sidebar browser is a separate surface. An unbound chat chooses a project explicitly; another chat's recent activity or tool results must never redirect an open canvas.

Closing Properties leaves it closed when selecting or creating an object. A compact contextual toolbar sits above the visible selection, with a below-selection fallback and viewport bounds. Selection bars reserve selected frame titles and the dimension badge so their controls cannot cover those labels. Text exposes named typography tokens or custom metrics, actual text colors, bold/italic/underline, safe links, native lists and alignment. Other objects expose fill, stack layout, corners and horizontal/vertical padding and stack margins. Both variants retain anchored comments and More actions for full Properties, duplicate, hide, lock/unlock and delete. Theme colors, typography and corner choices link real project tokens; custom edits detach only the changed property. The bar stays out of history, previews, libraries, component conversations and canvas gestures; hidden ancestry has no selection chrome. Text changes apply to the whole text layer.

Horizontal/vertical padding overrides legacy uniform stack insets and also pads an object's own content. Nonnegative margins affect only placement inside parent stacks, retaining free-positioned geometry. Italic style, plain-line list formatting and validated HTTP(S)/mailto/tel/fragment links persist in the same document and structured edits. Canvas preview and HTML/React exports share these settings without modifying embedded source. Editing a list preserves its original plain text; list markers are rendered. Links navigate in exported previews, respecting authored pointer events; native video playback takes precedence over a containing link.

The editor omits the top-right fullscreen action and the Play button beside the Inspector toggle. Frame labels show only their names. The editor has no screen-preview Play buttons or screen-preview modal.

The right Inspector and library editors have a draggable left edge with a remembered width, keyboard adjustment and double-click reset. Compact rounded menus share keyboard navigation and show actual swatches beside color-token values, including the selected value. Width preferences are local UI state and do not edit project history.

Related property rows share a label column so paired and full-width controls align. Narrow panels stack spacing rows and token menus where needed. Direct colors, including design-system tokens, have attached swatch pickers alongside editable CSS values or theme menus. Native pickers start from the current supported color and retain its nonzero alpha when a new color is chosen; transparent starts become visible after a deliberate pick.

Properties groups geometry into compact X/Y, width/height, rotation and flip controls. Parent-edge/center alignment uses the layer's visual bounds and respects padding and stack-owned positioning. Radius supports linked uniform values or four independent corners. Blending exposes layer opacity and supported native blend modes. Fill switches between solid, gradient and none without discarding stored settings; solid fill opacity preserves authored colors, while linear/radial gradients have 2–12 stable color stops, position/opacity, angle and sRGB/Oklab interpolation. Border, outline and existing shadows/effects remain editable. Changes use ordinary revisions and Undo; slider/stop gestures save once when accepted. Unsupported blend modes are disabled in the current browser. These properties persist through components, MCP edits, history and HTML/React/canvas-map exports; native CSS support determines destination rendering.

Linear-gradient angle combines a draggable circular dial with a decimal degree field. Shift, Command or Ctrl snaps the dial to 15° increments; unmodified arrows adjust by 1°, while pointer movement uses tenths of a degree. The dial follows CSS gradient orientation (0° up, 90° right), retains nearby turns and uses the existing −3,600°…3,600° limits. Local previews save once on release/key-up; Escape, pointer cancellation, lost capture, window blur or changed saved styles discard the gesture. Numeric entry uses the ordinary field save behavior.

Objects support ordered, editable drop shadows, inner shadows, text shadows, layer blur, background blur and transforms. Effects can be disabled without losing their parameters or removed deliberately; stable IDs and all settings persist in the document, history and MCP edits. Advanced exposes layering, clipping, cursor, pointer events, image fit, text overflow/decoration, box sizing, aspect ratio and CSS motion. Canvas/preview, focused context and HTML/React exports share the saved properties. Cursor, pointer events and CSS motion apply in preview/exports while the editor remains selectable. Transformed layers use accurate bounding outlines and parent-coordinate dragging; their dimensions remain editable through Properties instead of axis-aligned corner handles.

Dragging and corner resizing snap to nearby edges and centers within frames and between frames or free objects across the current canvas page. Subtle guides mark the active alignment. Snapping is on by default, can be switched in the zoom menu, and is bypassed while Option/Alt is held. Capture distance stays six screen pixels at any zoom. Stack positions remain managed by layout; locked/hidden ancestry cannot be moved through canvas gestures. Agent edits can invoke the same position-snapping calculation through a revision-checked operation. Guides and preferences do not enter the design document; the released geometry creates one ordinary saved change.

The Layers panel reveals new selections within its own scroll area. Reveal selected layer clears an excluding filter and reopens the component's ancestor path on request. Manual scrolling and collapsed branches stay under the user's control during ordinary property edits; revealing a layer never moves the canvas or takes keyboard focus.

Generated frames explicitly track building/ready state. While building, the live editor substitutes neutral grey for the frame background and draws a subtle wipe over incoming content. Two idle minutes stop motion and show Waiting for Codex; Properties can stop an interrupted indicator without losing content. Hidden/offscreen views and reduced-motion preferences suppress animation. Preview, history and visual exports preserve the authored appearance.

Design generation is progressive: frame shells appear early and their component groups and source fill in through successive saved batches. The live pane watches committed revisions and draws them as they arrive, preserving the user's viewport and selection. Do not stage an entire finished board for a delayed reveal or simulate model progress.

Every saved change records a complete project version. History previews are read-only and can be browsed without changing the live document; only the user's Apply action restores a selected version across all boards. A restore creates a new revision and keeps all earlier snapshots available. Existing projects begin history at their current saved state. The active change briefly flashes yellow on the canvas.

The primary user is a developer working alongside Codex. Success means the agent can create and edit the entire design through structured tools, the person can review any interface or slide on an infinite canvas and leave precise follow-ups, and an approved project provides complete source and context for implementation. The GaugeReel mobile flow is an optional example, not a limit on the workspace.

The desktop canvas is the primary surface. The user explicitly chose the Claude Design screenshots as the visual reference: dark neutral canvas, floating compact toolbars, project and page menus, screen flows, blue selection outlines, a right Properties/Code/Tweaks inspector, and anchored chat comments. Preserve this direction.

Projects persist on disk. Local browser mode and an MCP Apps view use the same document format. ChatGPT/Codex supplies intelligence through MCP tools and follow-up messages; the product must never simulate an assistant reply or imply that a queued comment has already been handled.

Platform: web desktop editor plus portable MCP plugin. Initial release is a local single-user workspace.

The original design prompt, 21 skills and 10 starter files are addressable through a read-only MCP catalog and paged verbatim reference reads. The agent entrypoint and MCP instructions route design creation through that material. Static JSX authoring instantiates the original packaged iOS, Android, macOS and browser-window functions, retaining JSX and passive HTML in a versioned source component. Internal markup remains source-editable rather than becoming separate native layers. Mobile artboards reserve blank safe areas by default; hardware/status chrome is explicit. The six browser-lifecycle starters remain source references with documented native canvas equivalents and unavailable original-host services.

Design system → DESIGN.md and Components offer a portable Download library ZIP; selecting a reusable definition also offers Download component. DESIGN.md includes generated token CSS, COMPONENTS.md provides usage snippets, and each component has a full Markdown reference with React/CSS, props and native JSON. The folder layout follows the imported create-design-system reference: root styles.css imports tokens/component CSS, named React JSX has sibling props declarations and prompt Markdown, and passive HTML specimen cards carry @dsCard metadata. A generated Agent Skill explains reuse. Source/React handoffs include the same library references.

The version-1 codex-design-library JSON envelope preserves the current typed native model, bindings, source and extensions. Importing a dedicated library ZIP or its JSON initializes a separate empty-canvas project with the library; components start a new local version baseline. Media bytes travel in the ZIP through the existing checksum-validated manifest and asset store. JSON alone requires those assets in the destination store. Library ZIP validation rejects unsupported versions and mismatched editable documents. Screens, conversations, inspiration, pending agent requests and prior version journals are excluded from dedicated library exports. Generated React represents visual structure with an empty props contract; original authored source remains available separately and is not executed by import. Installed fonts remain an environment dependency.
